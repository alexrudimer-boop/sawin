# Finite derived Hurwitz envelope

Date: 2026-06-03

This note records the refined finite-label object for route (1).  For a
finite nondegenerate set-theoretic YBE solution, the useful object is not the
raw pair of operator groups generated by `lambda_x` and `rho_x`.  It is the
guitar-conjugated derived Hurwitz envelope, plus a finite prefix group for
point-forgetting bookkeeping.

Write

```text
R(x,y)=(lambda_x(y), rho_y(x)).
```

The repository convention for the two-strand guitar map is

```text
J_2(x,y)=(lambda_x(y), x).
```

For a left-nondegenerate row, define the derived operation by the rule

```text
a*b = lambda_a(rho_y(b)),      where lambda_b(y)=a.
```

Equivalently, `y` is the unique preimage of `a` under the left action of
`b`.  The derived rack solution is then

```text
R_D(a,b)=(a*b,a).
```

The finite audit checks the convention

```text
J_2 R_X = R_D J_2.
```

For three strands, use reversed prefix labels:

```text
J_3(x,y,z)=(lambda_x lambda_y(z), lambda_x(y), x).
```

Then the original positive crossing on positions `i,i+1` is conjugated to
the derived rack crossing on the reversed adjacent positions.  The generated
audit checks this on all triples for a finite nondegenerate witness.

## Prefix bookkeeping

Interior point-forgetting is the tower subtlety.  In the same convention,
forgetting the middle input from `(x,y,z)` gives

```text
J_2(x,z)=(lambda_x(z),x),
```

while deleting the middle guitar label from `J_3(x,y,z)` gives

```text
(lambda_x lambda_y(z),x).
```

These need not agree.  Thus the unaugmented derived labels do not supply a
natural tower under interior point-forgetting.  The finite repair is to
augment the derived labels with prefix operators in the finite group

```text
L_X=<lambda_x:x in X> <= Sym(X).
```

Because `X` is finite and nondegenerate, `L_X` is a finite group.  This is
the bookkeeping piece that records how suffix labels must be recomputed after
forgetting a strand.

## Degenerate preimage gate

For genuinely left-degenerate rows, the derived operation can fail before any
Hurwitz envelope is available.  The finite obstruction is:

```text
lambda_b(y)=a
```

has no unique solution `y`, so the formula

```text
a*b=lambda_a(rho_y(b))
```

is not a total well-defined binary operation on `X`.

The generated audit records both failure types:

```text
missing_preimage
multiple_preimages_same_candidate
ambiguous_preimage_candidates
```

The last type is the strongest obstruction: two hidden neighbours with the
same visible label produce different derived outputs.  The first two already
show that the nondegenerate derived-rack envelope cannot be used without
additional finite memory.

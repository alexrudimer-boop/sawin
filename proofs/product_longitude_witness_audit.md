# Product longitude witness audit

## Purpose

This note records a sharper diagnostic for the product closed-label branch.
It prevents one false proof route and isolates a weaker route that is still
sufficient for the sharp finite-G implication.

The stronger current formulation is now the longitude-value subgroup
criterion in `proofs/product_longitude_subgroup_criterion.md`.  The per-label
witness search below remains a useful small diagnostic, but the theorem-level
target is membership of every closed product label in the subgroup generated
by all recursive-longitude values in the fixed product label group.

## The false common-assignment shortcut

A tempting product theorem would say:

```text
h_{z,j}(beta) = phi_z(L_j(beta))   for all j
```

for one homomorphism `phi_z:F_n -> H_prod` depending only on the initial
colour tuple `z`.  This is too strong.

The two-colour identity-base cyclic fixture in
`tests/test_product_permutation.py` gives a bounded counterexample to this
formula.  For the swapped product interval, colour tuple `(0,1,0)`, and braid
word

```text
sigma_1 sigma_2^2 sigma_1,
```

the closed product labels are nontrivial, but no assignment
`F_3 -> H_prod` makes the three coordinate labels equal the three
corresponding Artin longitude evaluations simultaneously.  The helper

```text
product_closed_label_common_longitude_assignments(...)
```

returns the empty tuple for this example.

This does not contradict the desired finite-G detector theorem.  The sharp
obstruction hypothesis says every longitude evaluates trivially under every
homomorphism into the detector group.  Therefore a proof may use different
homomorphisms for different coordinates, or different factors in an
expression for the same coordinate.

## Weaker sufficient witness condition

For a fixed finite product label group `H_prod`, a bounded diagnostic now
checks the following condition:

> For every nonidentity closed label `h_{z,j}(beta)`, there is some Artin
> longitude `L_i(beta)` and some homomorphism `phi:F_n -> H_prod` such that
> `phi(L_i(beta)) = h_{z,j}(beta)`.

If this condition were proved symbolically for all product local-minimal
intervals, all `n`, all base-fixed colour tuples, and all relevant braids,
then identity `H_prod` finite-group longitude data would force every closed
label to be identity.  The proof may choose `phi` after seeing the braid,
because `Lambda_{H_prod,n}(beta)=Lambda_{H_prod,n}(1)` quantifies over all
homomorphisms `F_n -> H_prod`.

The helper

```text
product_closed_label_longitude_witnesses(...)
```

returns explicit finite witnesses in this sense.  On the same
`sigma_1 sigma_2^2 sigma_1` fixture, the common-assignment shortcut fails,
but each of the three nonidentity closed labels is still hit by an Artin
longitude evaluation in `H_prod`.

The consolidated helper

```text
product_closed_label_longitude_route_audit(...)
```

records this same example in one object: zero common assignments, three
single-longitude rows, all rows inside the longitude-value subgroup, and no
failed rows.  The separate note `proofs/product_longitude_route_audit.md`
spells out the route ladder.

## Current implication for the product branch

This is still a bounded audit, not the all-`n` theorem.  Its value is that it
separates the correct product proof obligation from an unnecessarily strong
formula.  The product A-route should now prove one of the following symbolic
statements:

- the weaker witness condition above for every nonidentity closed product
  label; or
- a still broader factorization of each closed label as a product of
  finite-group Artin-longitude evaluations in a fixed detector group.

The second statement is now implemented directly by the finite fixed-word
audit

```text
product_closed_label_longitude_subgroup_audit(...)
```

which checks whether each closed label lies in the subgroup generated by all
longitude values under all assignments `F_n -> H_prod`.

A product B-route must do the opposite: exhibit closed labels that remain
nontrivial even when every Artin longitude is a law on every finite group.
The bounded helper
`product_closed_label_blind_movers(..., groups=[H_prod], ...)` checks only
the first finite group `H_prod`; an outcome B sequence must defeat all finite
groups by the diagonal normalized-law criterion.

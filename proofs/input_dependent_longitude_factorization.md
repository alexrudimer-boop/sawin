# Input-dependent longitude factorization criterion

## Purpose

This note records a theorem-level sufficient condition that is more flexible
than the coordinatewise product-label criterion and explains why multi-input
residual dependence is not automatically an obstruction.

The key point is that finite-group longitude identity quantifies over every
homomorphism `F_n -> G`.  Therefore, when proving that a braid acts trivially,
the homomorphism into the detector group may depend on the input fibre tuple.
This is exactly what happens for racks.

## Criterion

Let `pi:X -> Z` be a quotient over a base dominated by `Q`, and let
`N_n=ker rho_{Q,n}`.  Fix a finite group `G`, independent of `n`, acting on
each fibre in the residual branch under consideration.

Suppose that for every braid degree `n`, every base tuple `z in Z^n`, every
fibre tuple `x in X_z`, and every `beta in N_n`, the residual output can be
computed as follows.  For each coordinate `j`, there are:

- a finite list of Artin longitudes `L_{i_1}(beta),...,L_{i_r}(beta)`;
- homomorphisms `phi_1,...,phi_r:F_n -> G`, allowed to depend on
  `(n,z,x,j,beta)` or on any finite state canonically attached to these data;
- a fixed finite expression in the resulting elements of `G`;

such that the `j`-th residual output is obtained by applying that expression
to the appropriate input fibre point.  More simply, in the common single
factor case,

```text
delta_{n,z}(beta)(x)_j
  = phi_{n,z,x,j}(L_j(beta)) . x_j
```

after the braid permutation is known to be identity.

Then `G` detects the branch in the sharp kernel sense:

```text
Lambda_{G,n}(beta)=Lambda_{G,n}(1)  =>  delta_{n,z}(beta)(x)=x
```

for all `n,z,x,beta`.

## Proof

The hypothesis `Lambda_{G,n}(beta)=Lambda_{G,n}(1)` says that the Artin
permutation is identity and that every recursive longitude evaluates to the
identity under every homomorphism `F_n -> G`.  In particular, it evaluates to
the identity under the homomorphisms chosen after seeing the input tuple and
coordinate.  Every finite expression built from those evaluated longitude
values is therefore the identity element of `G`, so every residual coordinate
is fixed.  Since this holds for every fibre tuple, the residual action is
trivial.

The choice of homomorphism after seeing the input tuple is legitimate because
the finite-G longitude identity is universal over all assignments of the free
generators to elements of `G`.

## Rack example

For a finite rack `Y`, take

```text
G = Inn(Y) <= Sym(Y).
```

Given an input tuple `(y_1,...,y_n)`, define the homomorphism

```text
phi_y:F_n -> Inn(Y),    x_i |-> L_{y_i},
```

where `L_a(b)=a ▷ b`.  The rack braid action is

```text
rho_{Y,n}(beta)(y)_j
  = phi_y(L_j(beta))( y_{p(j)} ).
```

Thus racks fit the input-dependent criterion even though a single rack
crossing can have multi-input dependency support.  This is why the dependency
diagnostic in `proofs/residual_dependency_support.md` must not classify
multi-input support as a negative obstruction by itself.

The rack example also marks the limit of the coordinatewise formula.  If a
general braided set `X` admitted the same formula with values in `Sym(X)` for
the generator `sigma_i`, then `L_{i+1}(sigma_i)=1` and `p(i+1)=i` would force
the second output of `R_X(x,y)` to equal `x`.  Hence the formula is available
only in the rack-type case.  Non-rack solutions, including the identity
solution, require a more global finite-longitude factorization or the
quotient/residual branch machinery.

The executable helper

```text
rack_longitude_factorization(Y,beta,y)
```

returns the input-dependent assignment, braid permutation, evaluated
longitudes, and output tuple.  Unit tests verify that this factorization
agrees with the direct braid action on the three-point dihedral rack.

## Product branch as the coordinatewise special case

In a product-permutation branch, the homomorphisms often do not need to
depend on the input fibre tuple; the residual coordinate maps are finite
labels `h_{z,j}(beta)` acting coordinatewise.  The criterion above reduces to
`proofs/label_longitude_factorization.md` and
`proofs/product_longitude_witness_audit.md`: each closed label must be an
evaluation, or finite product of evaluations, of Artin longitudes in a fixed
finite label group.

## Remaining master-theorem target

The open Green/corridor problem can now be stated in a form that permits
multi-input dependence:

> For every local-minimal interval outside the already known branches,
> construct a finite group `G(pi,Q)`, independent of `n`, and prove an
> input-dependent longitude factorization of the residual action through
> `G(pi,Q)`.

A slightly more algebraic equivalent target is the longitude-value subgroup
form.  For a fixed finite detector group `G` and braid `beta`, form the
subgroup generated by all values of all recursive Artin longitudes under all
assignments `F_n -> G`.  If every residual coordinate holonomy element for
`beta` lies in this subgroup, then identity finite-`G` longitude data kills
the residual action.  This is implemented by `longitude_value_generators()`
and `longitude_value_subgroup_elements()` and specialized to product labels
in `proofs/product_longitude_subgroup_criterion.md`.

If this is possible, the sharp obstruction theorem supplies the finite rack
detector.  If it is impossible, a counterexample must produce a
normalized-law sequence whose residual motion is not expressible through
input-dependent evaluations in any fixed finite group.
